# MarkIt 架构总览

> 文档定位：面向接手本仓库的开发者的整体架构说明，覆盖进程边界、模块职责、构建链路、启动时序与关键数据流。
> 适用读者：需要新增功能、修改 IPC、排查跨进程问题或进行代码评审的开发者。
> 代码基线：MarkIt v1.5.0，`develop` 分支，文档基线同步 2026-11-10。文中结论均以源码为准，接口细节见 [IPC 接口与进程契约](./IPC接口与进程契约.md)。

## 1. 产品定位与能力边界

### 1.1 定位

MarkIt 是一款**本地优先**的 Markdown 桌面编辑器：以单个文件为操作单位，编辑、实时预览、图表渲染与 PDF 导出全部在本机完成，不依赖账号、云端或网络服务（自动更新除外）。工程是**单包 npm 工程**，构建工具为 `electron-vite`，技术底座为 Electron + Vue 3 + TypeScript。

### 1.3 明确不在范围内

- **无云端能力**：没有账号、同步、协作、遥测与崩溃上报；除自动更新检查外不发起网络请求。
- **无工作区概念**：不维护目录树、文件索引、全局搜索或 Git 集成，一次只处理用户显式打开的文件。
- **无插件体系**：没有插件市场或第三方扩展点；自定义预览 CSS 只在当前运行期生效。
- **非所见即所得**：编辑区只编辑 Markdown 源文本，预览区只读渲染，不支持在预览中直接编辑。
- **只处理 UTF-8 文本**：不做编码嗅探与转换；图片仅通过只读协议展示，不编辑二进制文件。
- **工程边界**：单包 npm（非 monorepo），已引入 Vitest（纯函数）与 Playwright（Electron e2e），但没有 git 钩子；质量门槛为 `lint` / `typecheck` / `npm test` 与手工验证。

## 3. 进程模型

MarkIt 使用 Electron 标准三层结构，另有一个**仅存在于编译期**的共享类型目录。

```mermaid

  subgraph OS["操作系统 / 外部"]
    FS["文件系统"]
    SHELL["默认浏览器 / 资源管理器"]
    APPHUB["apphub 更新端点"]
  end

  subgraph MAIN["主进程 src/main"]
    MI["index.ts<br/>窗口 / IPC / 文件读写 / 协议 / PDF / 会话"]
    MU["updater.ts<br/>electron-updater 双通道状态机"]

  subgraph RENDERER["渲染进程 src/renderer"]

  end

  SHARED["src/shared<br/>session / update / file / pdf types<br/>纯类型，无运行时依赖"]

  FS <--> MI
```

### 3.1 边界规则

1. **主进程独占 Node / Electron 能力**：文件读写、对话框、窗口、协议、自动更新、PDF 打印均只在 `src/main` 实现。
2. **渲染进程是纯 Web 环境**：禁止 `import ... from 'electron'`（已核实 `src/renderer` 下 0 处），只能调用 preload 暴露的 `window.api`；不暴露通用 `ipcRenderer` / `process`。
3. **新增 IPC 必须三处同步**：主进程 `registerHandle` / `registerOn`（[`ipc-guard.ts`](../../src/main/ipc-guard.ts) 校验调用来源）→ preload `ipcRenderer.invoke` / `send` → [`src/preload/index.d.ts`](../../src/preload/index.d.ts) 的类型声明。`ExposedAPI = typeof api` 是唯一契约来源。
4. **`src/shared` 只放纯类型**：`session-types.ts`、`update-types.ts`、`file-types.ts`、`pdf-types.ts`、`image-types.ts`、`integration-types.ts` 不含任何运行时依赖，供主进程与渲染进程共同 `import type`。
5. **preload 关闭沙箱**：各应用窗口的 `webPreferences` 都是 `sandbox: false`，preload 依赖 `process.platform`、`process.contextIsolated` 与 `ipcRenderer`；这不是开放 `nodeIntegration`，渲染进程仍无 Node 全局。
6. **外部导航一律离开编辑窗口**：`setWindowOpenHandler` 与 `will-navigate` 双重兜底，只允许 `http/https/mailto` 交给系统，`file:` 定位到资源管理器，其余协议忽略。

## 5. 三个渲染入口与引导链路

`electron.vite.config.ts` 的 `renderer.build.rollupOptions.input` 显式声明了三个 HTML 入口，因此这是**多页构建**，不是单页路由。

### 5.1 编辑窗口：`index.html`

- `src/renderer/index.html` 通过 `<script type="module" src="/src/main.ts">` 引导，可同时创建多个编辑窗口。
- `main.ts` 执行 `createApp(App).use(createPinia()).mount('#app')`。
- `App.vue` 的 setup 阶段完成：
  - 顶层组合式函数：`useOutline` / `useKeyboardShortcuts` / `useScrollbarState` / `useWindowZoom` / `useFileWatcher` / `useSession` / `update.init()`。
  - 监听 `window:close-request` → `saveAllBeforeExit()` → `window.api.close()`，只关闭当前编辑窗口。
  - 监听 `app:prepare-exit` → `saveAllBeforeExit()` → `completePrepareExit()`，参与应用退出 / 更新安装的多窗口协调。
- 模板由 `AppLayout` + `ConfirmDialog` + `UpdateNotice` 组成。
- `AppLayout` 内部：`TitleBar`（内含 `TabBar`）/ `Toolbar` / `OutlinePanel` / `SplitPane`（`EditorPane` + `MarkdownPreview`）或单栏编辑器 / 预览 / `StatusBar` / `PdfExportDialog`。设置页不在编辑窗口内渲染。

`App.vue` 是单个编辑窗口的**生命周期协调者**：窗口内会话恢复、文件监听注册、关闭前保存和退出 / 安装前保存都在这里串起来；跨窗口协调由主进程负责。

### 5.2 更新详情窗口：`update.html`

- `src/renderer/update.html` 通过 `<script type="module" src="/src/update/main.ts">` 引导。
- `update/main.ts` 执行 `createApp(UpdateWindow).use(createPinia()).mount('#app')`。
- `UpdateWindow.vue` 的职责：
  - `update.init()`：订阅 `update:state` 并读取当前状态。
  - 主题：`localStorage('markit-theme')` + 系统媒体查询 + `storage` 事件。
  - 下载：`window.api.update.download()`。
  - 安装：`window.api.update.requestInstall()`，由主进程统一协调所有编辑窗口处理未保存内容。
  - 关闭：`window.api.update.closeWindow()`。

所有编辑窗口与更新窗口各有独立 Pinia，不共享内存状态；更新状态通过主进程 `update:state` 广播，主题通过 localStorage 的 `storage` 事件同步。

### 5.3 设置窗口：`settings.html`

- `src/renderer/settings.html` 通过 `<script type="module" src="/src/settings/main.ts">` 引导。
- `settings/main.ts` 执行 `createApp(SettingsWindow).use(createPinia()).mount('#app')`。
- `SettingsWindow.vue` 使用应用偏好 store、预览样式 store 和更新 store，按分类展示外观、编辑与预览、编辑器集成、更新、关于。
- 设置窗口用 `titleBarOverlay` / macOS 交通灯复用系统窗口按键，页面只提供 36px 拖动区，不绘制自定义关闭按钮。
- 全局偏好写入 `markit-*` localStorage；所有编辑窗口和设置窗口都监听 `storage` 事件刷新内存状态。`markit-layout` 仍按标签保存，不参与同步。
- 安装更新时调用 `update:request-install`，主进程通知所有编辑窗口执行 `saveAllBeforeExit()`，全部成功后才安装。设置窗口从不直接保存编辑器文档。
- 设置窗口是全局单实例工具窗口，不进入编辑窗口注册表，也不参与会话恢复。

### 5.4 三个入口的差异

| 维度 | 编辑窗口（可多个） | 更新详情窗口 | 设置窗口 |
| --------- | ---------------------------------- | -------------------------------------- |
| 入口 HTML | `src/renderer/index.html` | `src/renderer/update.html` | `src/renderer/settings.html` |
| 挂载组件 | `App.vue` | `update/UpdateWindow.vue` | `settings/SettingsWindow.vue` |
| 预加载 | 同一个 `src/preload/index.ts` | 同一个 preload | 同一个 preload |
| 状态 | 文档 / 编辑器 / 应用 / 样式 / 更新（每窗口独立 Pinia） | 只使用更新 store | 应用 / 样式 / 更新（独立 Pinia） |
| 安装动作 | 参与主进程协调，保存本窗口后等待统一安装 | 只发起请求，不直接安装 | 只发起请求，不直接安装 |
| 开发 URL | `${ELECTRON_RENDERER_URL}` | `${ELECTRON_RENDERER_URL}/update.html` | `${ELECTRON_RENDERER_URL}/settings.html` |
| 生产文件 | `out/renderer/index.html` | `out/renderer/update.html` | `out/renderer/settings.html` |

## 7. 启动时序

主进程在模块加载阶段就注册协议方案（必须早于 `app ready`），随后才进入单实例判断与窗口创建。

```mermaid
sequenceDiagram
  autonumber
  participant OS as 系统
  participant Main as 主进程
  participant Preload as preload
  participant Renderer as 渲染进程
  participant Updater as electron-updater

  Main->>Main: protocol.registerSchemesAsPrivileged('markit-file')
  Main->>Main: app.requestSingleInstanceLock()
  alt 未获得锁（已有实例）

    Main->>Updater: initAutoUpdater()（开发模式 status = disabled）
    Main->>Main: 启动 300ms 光标坐标推送定时器
    Main->>Main: extractFilePaths(process.argv) → 最后聚焦窗口队列
    Renderer->>Preload: 加载页面并执行 App.vue setup
    Preload->>Main: ipcRenderer.send('renderer:ready')

    Note over Main,Updater: 生产环境：启动 3s 后静默 checkForUpdates()
  end
```

### 7.1 时序中的关键设计

1. **`renderer:ready` 而不是 `did-finish-load`**：`did-finish-load` 触发时 `webContents.isLoading()` 仍可能为 `true`，直接发送会丢失；`preload` 在 `onOpenFile` 注册监听后才上报就绪。每个窗口的 `did-start-loading` 只重置自己的 `rendererReady`。
2. **文件排队**：首次启动的 argv 文件、启动期间 `second-instance` 转发的文件、以及异步读取期间发生重载的文件，统一进入目标编辑窗口自己的 `pendingFilePaths`，由该窗口的 `renderer:ready` 放行。
3. **会话恢复是第二道闸门**：渲染进程收到 `open-file-from-argv` 时若恢复尚未完成，会先存入 `pendingOpenFiles`；`restore()` 结束后再统一打开，避免刚打开的文件被恢复结果整体替换。
4. **更新检测延迟 3 秒**：避免与首屏渲染、文件读取抢资源；开发模式不检测，状态直接为 `disabled`。

### 7.2 关闭与退出

每个编辑窗口的 `close` 事件在自身 `allowClose !== true` 时拦截，并发送 `window:close-request { quit: false }`。渲染进程逐个确认该窗口的已修改标签，保存会话后调用 `window.api.close()`；主进程只关闭发送方窗口。应用退出由 `before-quit` 统一向所有编辑窗口发送 `app:prepare-exit(kind=quit)`，全部窗口确认保存后才真正退出；安装更新使用同一协调链路。窗口关闭标志按窗口独立，Dock 重新开窗后仍会触发未保存确认。

### 8.4 会话恢复

1. 主进程读取 `session.json` v2，按窗口切片创建多个编辑窗口；旧版单窗口结构自动迁移。
2. `useSession()` 在 `App.vue` setup 阶段注册 `onOpenFile` 监听（preload 随即发送 `renderer:ready`），并调用 `window:get-context` 获取当前窗口 ID。
3. `onMounted` 调用 `session:load`；主进程只返回发送方窗口的切片。对每个有路径的标签调用 `file:read`，成功则以磁盘内容覆盖会话内容，失败保留会话内容。
4. `documents.restoreSession()` 清空 `EditorState` / 滚动缓存，整体替换标签并还原激活下标；标签迁移窗口随后发送 `window:ack-tab-transfer`。
5. `markSessionReady()` 放行 `whenSessionReady()` 的等待者；随后打开 `pendingOpenFiles`。
6. 编辑期间以 800ms 防抖写回当前窗口切片；主进程聚合全部窗口并原子写入 `session.json`。

### 8.5 PDF 导出

1. `PdfExportDialog` 收集 `pageSize` / `margin` / `showPageNumbers` / `showToc` / `showFrontmatter` / `fileName` / `sourcePath`，`AppLayout` 调用 `usePdfExport().exportPdf(options)`；确认后对话框收束到状态栏导出锚点，状态栏展示阶段百分比、细进度条和最终结果。
2. 渲染进程用 `createMarkdownRenderer()` 创建的独立实例渲染 frontmatter 表格与正文（含 GitHub 任务列表），安装同一套本地图片规则与 `heading-N` 锚点；`showToc` 为真时用 `parseHeadings` 生成目录，`showFrontmatter` 为真时输出「文档信息」表格；图表通过共享 `renderDiagramSvg()` 优先 Pele、失败回退 Mermaid 并内联为 SVG，拼成带固定 CSS 的自包含 HTML。
3. `window.api.exportPdf(html, options, requestId)` → 主进程先弹保存对话框（`defaultPath` 由 `fileName` 与文档目录 `sourcePath` 组合），校验 HTML 体积（> 64MB 明确提示），写入临时文件后由隐藏 `BrowserWindow` `loadFile`；阶段进度只发送给发起窗口。
4. 主进程等待所有 `<img>` 的 `load` / `error`、`document.fonts.ready` 与两帧布局（1500ms 兜底），然后 `printToPDF({ pageSize, margins, displayHeaderFooter, footerTemplate, printBackground: true })`，写盘并返回路径；`finally` 销毁隐藏窗口并删除临时文件。
5. 页边距映射为 0.4 / 0.65 / 0.9 英寸（Electron `printToPDF.margins` 按英寸处理），页码通过页脚模板输出；图表双渲染失败时可见降级，分页通过 `break-inside` / `thead` / `tr` 规则约束，剩余限制见 [技术决策与已知限制](./技术决策与已知限制.md)。

### 8.6 长图导出

1. 工具栏“导出长图”先打开 `ImageExportDialog`；设置持久化在 `markit-image-export-settings`。确认后对话框收束到状态栏导出锚点。
2. 调用 `useImageExport(options)`，按正文宽度 640 / 800 / 1000 / 1200 px、1× / 2×、主题和 Frontmatter 选项生成自包含 HTML。
3. `window.api.exportImage(html, options, requestId)` → 主进程弹保存对话框，写入临时 HTML，由按画布宽度配置的隐藏 `BrowserWindow` 加载；隐藏窗口关闭后台节流。
4. 主进程测量固定画布宽度和完整内容高度，选择实际倍率，将隐藏窗口调整为完整长图视口并用 `webContents.capturePage()` 输出 PNG 或高质量 JPEG，校正扩展名并返回 `ImageExportResult`。阶段进度在单次截图前推进到“生成图片”，截图期间由流动进度条表示仍在工作。
5. 页面加载、尺寸测量和截图均有兜底超时，异常或超时会释放 UI 并明确失败；高度或像素预算仍超限时也会中止。`finally` 销毁隐藏窗口并删除临时文件。完整边界见[图片导出](../导出/图片导出.md)与[图片导出设置方案](../导出/图片导出设置方案.md)。

## 9. 目录结构与命名约定

### 9.1 顶层目录

| 目录 / 文件      | 职责                                                  |
| ---------------- | ----------------------------------------------------- |
| `src/main/`      | 主进程：窗口、生命周期、文件、协议、PDF、自动更新     |
| `src/preload/`   | `contextBridge` 白名单 API 与类型声明                 |
| `src/shared/`    | 跨进程纯类型，禁止运行时依赖                          |
| `src/renderer/`  | 三个 HTML 入口与 Vue 渲染进程                         |
| `resources/`     | 运行时资源：图标与 VSCode 扩展源码，`asarUnpack` 解包 |
| `build/`         | 安装包图标与签名相关资源                              |
| `scripts/`       | 一次性构建 / 发版脚本，不打进安装包                   |
| `docs/`          | 设计与发版文档，不打进安装包                          |
| `rules/`         | AI 与协作规则                                         |
| `out/` / `dist/` | 构建产物 / 安装包产物（均被 gitignore）               |

### 9.2 命名约定

| 对象                     | 风格                              | 示例                                              |
| ------------------------ | --------------------------------- | ------------------------------------------------- |
| 变量、函数、参数         | camelCase                         | `openFile`、`windowContext.zoomFactor`            |
| 类、接口、类型、Vue 组件 | PascalCase                        | `SessionData`、`MarkdownPreview`                  |
| 常量                     | UPPER_SNAKE_CASE                  | `LOCAL_FILE_SCHEME`、`MERMAID_LANGUAGES`          |
| Vue 组件文件             | PascalCase，按领域分目录          | `components/editor/EditorToolbar.vue`             |
| Composable               | `useXxx.ts`（camelCase）          | `useFile.ts`、`useScrollSync.ts`                  |
| 工具、store 等非组件 ts  | kebab-case                        | `text-diff.ts`、`local-image.ts`                  |
| 入口文件                 | `index.ts` / `main.ts`            | `src/main/index.ts`、`src/renderer/src/main.ts`   |
| IPC 通道                 | `模块:动作`                       | `file:read`、`window:get-zoom`、`update:download` |
| localStorage 键          | `markit-` 前缀，集中在 store 读写 | `markit-theme`、`markit-layout`                   |
| 自定义协议               | `markit-file://`                  | 仅用于预览图片                                    |

### 9.3 代码风格基线

- Prettier：无分号、单引号、2 空格、`printWidth: 100`、无尾逗号；UTF-8、LF、文件末尾空行。
- 新增业务源码文件首行携带 `作者 / 创建 / 描述` 头部注释；存量文件不强制回补。
- 日志只用 `console.error` / `console.warn`，文案为简短英文；禁止遗留 `console.log`。
- 注释、文档、界面文案使用中文；界面与文档中的品牌名统一写 **MarkIt**，安装包产品名保持 `Mark It`。
- 渲染进程不直接操作 DOM 绕过状态；编辑器 / 预览等必须操作 DOM 的场景通过 `ref` + 显式初始化函数封装。
