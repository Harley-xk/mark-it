# MarkIt 公开发布整改计划

> 文档定位：MarkIt 从「内测 / 小范围试用」走向「公开发布」的总体整改计划，统一记录安全加固、分发信任、数据可靠性与公开发布所需体验的待办、验收标准与执行进度。
> 代码基线：`1.6.0-beta.13`，`develop` 分支，核实日期 2026-11-16。
> 关联文档：[待整改清单](./待整改清单.md)、[技术决策与已知限制](../架构与契约/技术决策与已知限制.md)、[渲染安全与内容沙箱](../架构与契约/渲染安全与内容沙箱.md)、[测试与质量保障](./测试与质量保障.md)。

## 1. 背景与目标

MarkIt 目前仅由维护者与少量同事使用，功能完整度已经较高，但公开发布意味着两件事发生了变化：

1. **文档来源不再可信**。用户会打开别人发来的 Markdown。只要渲染管线允许文档内容执行脚本，就等于把本机文件读写能力交给文档作者。
2. **安装包需要被系统信任**。未签名 / 未公证的安装包会被 SmartScreen、Gatekeeper 拦截，自动更新也无法可靠工作。

本计划的目标是：在公开发布前，把「打开一份不受信任的 Markdown」的风险降到可接受范围，让三平台安装包具备可分发的基本信任，并让用户遇到问题时能提供可诊断的信息。

## 2. 范围与非目标

**范围**

- 渲染内容的安全边界（清洗、CSP、权限、导出窗口隔离）
- 安装包签名、公证与 Electron 运行时加固
- 文件读写、编码、崩溃等数据可靠性与可诊断性
- 公开发布必需的隐私说明、发布物料与 CI 门禁
- 面向公开用户的基础体验补齐

**非目标**

- 预览增量渲染与 Worker 化（见 [预览渲染后续优化计划](../计划功能/预览渲染后续优化计划.md)）
- 协作、云同步、插件系统
- 账号体系与商业化能力

## 5. 安全（SEC）

### SEC-01 渲染内容统一清洗

- **问题**：`markdown-it` 开启 `html: true`，预览通过 `innerHTML` 注入，未做任何清洗。恶意文档中的 `<img onerror>`、`<svg onload>` 等事件属性会执行，并可调用 preload 暴露的 `readFile` / `saveFile`。
- **影响**：读取任意本地文件并外传；向任意路径写入内容（包括启动目录），形成持久化风险。
- **整改**：新增统一的 `utils/sanitize.ts`，在预览渲染出口与导出 HTML 构建入口做 DOMPurify 清洗；放行 `markit-file:`、`data:image`、`file:` 与标题锚点所需属性，确保本地图片、大纲锚点、任务列表不受影响。
- **验收**：`<script>`、`<img onerror>`、`javascript:` 链接、`<iframe>` 清洗后均不可执行；`<kbd>`、`<mark>`、任务列表、本地图片、标题锚点保持正常；补充 Vitest 回归用例。

### SEC-02 导出 HTML 与隐藏窗口隔离

- **问题**：PDF / 长图导出先在渲染进程用 `innerHTML` 组装 HTML，再写入临时文件由隐藏窗口 `loadFile`；后者会真正执行 `<script>`。PDF 窗口当前还是 `sandbox: false`，且导出窗口没有导航与新窗口兜底。
- **整改**：导出前统一清洗；导出 HTML 注入 `script-src 'none'` 的 CSP；隐藏窗口开启 `sandbox`、拒绝导航与新窗口。
- **验收**：包含恶意 HTML 的文档导出 PDF / 长图时不执行脚本，产物内容与正常文档一致；PDF 页码、目录、长图尺寸不受影响。

### SEC-03 Mermaid 安全等级

- **问题**：`securityLevel: 'loose'` 允许 HTML 标签与 `click` 回调，SVG 又直接注入 DOM。
- **整改**：改为 `'strict'`，禁用交互式 `click` 与未转义标签。
- **验收**：内置手册中的全部图表类型正常渲染；`click` 语法不再产生可点击回调。

### SEC-04 生产 CSP

- **问题**：三个渲染入口均无 CSP；XSS 一旦出现可直接加载远程脚本、iframe 与外传数据。
- **整改**：构建时向 `index.html` / `settings.html` / `update.html` 注入生产 CSP，限制脚本、连接、框架与对象；开发模式不注入，避免影响 Vite HMR。
- **验收**：打包产物中三个 HTML 均带 CSP；应用启动、预览、设置、更新窗口功能正常；外链资源与本地图片按白名单加载。

### SEC-05 权限请求默认拒绝

- **问题**：未设置 `setPermissionRequestHandler`，Electron 默认放行权限请求，页面可申请摄像头、麦克风、地理位置等。
- **整改**：默认拒绝全部权限请求与权限检查；如后续确需剪贴板等能力，再逐项放行。
- **验收**：在预览中尝试 `getUserMedia` / 地理位置时被拒绝且不弹系统授权；现有编辑与复制粘贴不受影响。

### SEC-06 设置 / 更新窗口导航兜底

- **问题**：编辑窗有 `will-navigate` 与 `setWindowOpenHandler`，设置窗只有后者，更新窗两者都没有。
- **整改**：三个窗口统一：非应用页面导航一律阻止，新窗口一律拒绝。
- **验收**：在任意窗口内触发外链或导航时，主窗口不会被带走。

### SEC-07 收紧 `markit-file://` 协议特权

- **问题**：协议注册带 `bypassCSP: true` 与 `supportFetchAPI: true`，前者会让 CSP 对本地图片失效，后者扩大渲染进程对图片文件的读取面。
- **整改**：移除 `bypassCSP` 与 `supportFetchAPI`，改由 CSP 的 `img-src` 明确放行 `markit-file:`。
- **验收**：预览中的相对 / 绝对路径图片正常显示；CSP 生效后 `markit-file:` 仍可加载；非图片扩展名仍被拒绝。

### SEC-08 窗口 sandbox

- **问题**：编辑窗、设置窗、更新窗均为 `sandbox: false`（PDF 导出窗同样）。
- **整改**：preload 仅依赖 `electron`，开启 `sandbox: true`；导出窗口同步开启。
- **验收**：`npm run dev` 与打包产物下窗口正常创建，`window.api` 可用，文件、会话、更新、导出链路正常。

### SEC-09 主进程文件读写路径收敛（防御纵深）

- **问题**：`file:read` / `file:save` 接受渲染进程传入的任意路径，清洗失效时仍可读写任意文件。
- **整改**：在主进程维护「用户通过对话框、系统打开事件或会话恢复接触过的路径」集合，拒绝集合外路径；至少拒绝写入应用自身目录与开机启动目录。
- **验收**：正常打开 / 保存 / 另存为不受影响；渲染进程伪造任意路径调用被拒绝。

## 6. 分发与信任（REL）

### REL-01 macOS 签名与公证

当前 `notarize: false`，未签名应用会被 Gatekeeper 拦截，Squirrel.Mac 不执行自动更新。公开发布若包含 macOS，必须配置 Apple Developer 证书、`hardenedRuntime` 与公证流程；否则需在下载页明确标注「仅支持手动安装」。

### REL-02 Windows 代码签名与钩子顺序

未签名安装包会触发 SmartScreen。启用签名前必须把 `scripts/after-sign.cjs` 中改写 exe 版本资源的逻辑迁到 `afterPack`（签名之前），否则签名会失效。

### REL-03 Electron Fuses

建议在首个公开版本启用：`runAsNode: false`、关闭 `NODE_OPTIONS` 与 `--inspect`、`onlyLoadAppFromAsar`、`enableEmbeddedAsarIntegrityValidation`。ASAR 完整性校验一旦错过首个版本，后续再开启会破坏存量客户端的升级路径。

### REL-04 CI 门禁

当前发版 CI 只运行 `npm test`，lint 不在 CI 中。建议增加 `npm run lint`，并接入 `npm audit` 或依赖更新机器人。

### REL-05 活跃度上报开关与隐私政策

上报字段不包含文件路径与文档内容，但没有用户开关，且仅在用户手册中说明。公开发布前建议：设置页增加「使用统计」开关、补隐私政策、在关于页与首次启动说明。上报用的 HMAC secret 编译在客户端内，可被提取，不应视为安全边界。

### REL-06 发布物料与仓库元信息

`package.json` 的 `homepage` 仍指向 `electron-vite.org`，缺少 `repository`；仓库缺 SECURITY.md、CHANGELOG、issue 模板。建议公开发布前补齐。

### REL-07 移除无用的 macOS 权限描述

`electron-builder.yml` 声明了摄像头、麦克风等使用说明，但应用并不需要这些能力，建议删除，避免给用户错误预期。

## 7. 数据安全与可诊断性（DATA）

### DATA-01 保存失败反馈

`file:save` 抛错后渲染层没有捕获，磁盘满、无权限、文件被占用时用户看不到任何提示。建议弹出含路径与原因的错误框，提供「重试 / 另存为」，并保持标签的未保存状态。

### DATA-02 打开 / 读取失败反馈

多选打开时读取失败只写控制台；右键、命令行、VSCode 打开失败同样静默。建议汇总提示失败文件；文件被删除时在标签上显示状态。

### DATA-03 非 UTF-8 检测与写回保护

当前读写固定 UTF-8，GBK 等编码会出现替换字符，保存后原文件被破坏。建议检测非法字节并提示「以只读打开 / 转换编码」，禁止静默回写。

### DATA-04 文件大小上限与会话快照边界

打开文件没有大小上限，全文进入 800 ms 会话快照。建议设置可配置阈值（如 5 / 10 MB），超大文档提示只读或限制预览，且不进入会话快照。

### DATA-05 崩溃捕获与日志

仓库没有 `uncaughtException`、`unhandledRejection`、`render-process-gone` 处理，也没有日志文件。建议增加滚动日志与设置页「导出诊断日志」，便于公开用户反馈问题。

## 10. 验收方式

1. 每批改动完成后执行 `npm run lint`、`npm run typecheck`、`npm test`。
2. 涉及主进程、窗口、IPC、导出的改动，执行 `npm run build` 与 `npm run test:e2e`；条件允许时用 `npm run dev` 实际启动验证。
3. 安全项额外按 [测试与质量保障](./测试与质量保障.md) 的恶意文档矩阵手工验证。
4. 状态更新规则：代码合入且自动化通过记为 🟡；完成该条的手工验收后再改为 ✅。
